# Deep web research

Use this workflow for a substantial investigation. It coordinates the installed tools; it does not replace live searches with model recollection.

## 1. Define a research contract

Record the decision, audience, geography, date window, constraints and deliverable. Use the current runtime date. Ask only for missing information that materially changes the work; otherwise record assumptions. If budgets are unspecified, start with a bounded discovery pass rather than an unlimited crawl.

Conserva un brief breve, registro de consultas, ledger de fuentes y hallazgos en una ubicación autorizada del proyecto. No confirmes ni publiques automáticamente texto de fuentes ni datos personales.

## 2. Build complementary search lanes

For a wide first pass, use 3–5 independent lanes, each with a concrete question and a bounded query budget. Useful lanes include:

- Primary product documentation, release notes, prices and limitations.
- Customer pain, procurement requests, job postings, reviews and public support discussions.
- Existing competitors, substitutes, distribution and pricing.
- Academic evidence, empirical evaluations and failure modes.
- Regulation, licensing, privacy, operating costs and reasons the idea might fail.

Search in the audience's language and English where useful. Use synonyms, domain-specific terms, narrower verticals, date filters and counterqueries. Do not append the current year to every query: foundational evidence and unsuccessful older approaches also matter.

Delegate independent lanes only when useful. Give each delegate an exact question, bounds and the same citation/privacy rules. Join their results and reconcile contradictions; delegate agreement alone is not independent corroboration.

## 3. Use available capabilities deliberately

Choose only the search, browser, public-page reader, academic index and technical-documentation tools exposed in the current session. Do not assume a specific MCP, local wrapper, package, model or API key exists. If a capability is unavailable or rate-limited, record that limitation instead of installing software, changing identities or bypassing access controls.

Keep remote queries public. Do not send credentials, private code, customer data or confidential plans to external research services.

## 4. Inspect and preserve the evidence

Open the actual source behind each important search result. Record its URL, author or organization, publication/update date if known, UTC retrieval time, source type, relevant excerpt and limitations. Label unreadable sources and snippet-only evidence explicitly.

If a response is truncated, continue from its documented offset or read relevant sections before claiming completeness. Do not repeatedly refetch the same first chunk. Preserve context around quotations and compare updated documentation with the version/date being investigated.

For each decision-critical claim, seek an independent corroborating source and disconfirming evidence. Multiple copies of one press release are one source. Vendor testimonials, affiliate pages and anonymous revenue screenshots remain unverified unless supported by stronger evidence.

Treat a page date inferred from metadata as uncertain; do not present an estimated date as a known publication date. A lack of search results is not proof something does not exist.

## 5. Synthesize and stop honestly

Produce an evidence table, alternatives, contradictions, confidence per major conclusion and unresolved questions. Separate observed facts, estimates, assumptions and recommendations. Cite sources next to the claims they support.

Stop when key questions have adequate coverage or the agreed effort boundary is reached. Report the actual coverage and limitations; never claim to have read "the entire internet" or every outbound link.

For business opportunities, continue with `ai-opportunity-validation` before recommending spending or promising results.
